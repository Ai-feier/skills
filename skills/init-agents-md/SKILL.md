# init-agents-md Skill

## 概述

此 skill 用于在项目根目录生成 `AGENTS.md` 文件，包含 AI 工作的文档治理规范。

## 使用方式

在项目中执行：

```
/init-agents-md
```

## 工作流程

1. 检查项目根目录是否已存在 `AGENTS.md`
2. 如果存在 → 提示用户选择覆盖或跳过
3. 如果不存在 → 写入模板内容
4. 显示成功消息

## AGENTS.md 模板

```markdown
# AGENTS.md

> 此文件是 AI 在本仓库工作的入口地图。保持精简（<100 行）。
> 原则：地图，不是百科全书。

## 文档治理

### 铁律
- **禁止自主创建**：AI 不得自行创建任何文档（README、CHANGELOG、设计文档等），必须先请求人工批准
- **禁止自主修改**：AI 修改文档前必须说明修改内容和原因，获得人工同意
- **简洁优先**：文档用最少的字表达必要信息，冗余即错误

### 渐进式文档策略
- 项目初期只维护此文件，不创建额外文档
- 需要新文档时，AI 提出请求 → 人工审批 → AI 执行
- 文档随项目复杂度增长而增长，不超前创建

## 仓库结构

[项目维护者在此描述关键目录和模块]

## 编码规范

[项目维护者在此添加技术栈相关规范]

## 渐进式披露索引

当项目逐步成长时，按需添加以下文档并在此索引：
- `docs/ARCHITECTURE.md` — 系统架构和模块边界
- `docs/DESIGN.md` — 设计决策和核心信念
- `docs/QUALITY.md` — 质量标准和评分

> 空索引是正常的。文档应在真正需要时才创建，且必须经人工批准。
```

## 实现细节

### 检查文件存在性
使用 `os.path.exists()` 检查项目根目录是否存在 `AGENTS.md` 文件。

### 写入模板内容
如果文件不存在，将上述模板内容写入 `AGENTS.md` 文件。

### 用户交互
如果文件已存在，提示用户选择：
- 覆盖现有文件
- 跳过创建，保持现有文件

### 错误处理
- 捕获文件写入异常
- 显示友好的错误消息
- 确保操作原子性
